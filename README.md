# DeskTidy —— 桌面收纳盒

把桌面上散落的文件收进具名收纳盒，桌面清爽；要用了再拿出来。
**本工具绝不删除任何文件，也绝不覆盖任何已存在文件。**

---

## 它做什么

桌面上东西太多看着乱，但真删又不敢删——DeskTidy 就是给这种情况准备的。

点一下「收纳桌面」，桌面上的文件和文件夹被**真实移动**到：

```
%USERPROFILE%\DeskTidy\<盒名>\
```

桌面立刻干净。想拿回来，双击那一条，或者点「撤销上次收纳」整批还原。

**还能把收纳盒做成桌面浮窗**：每个盒子一个小窗常驻在桌面上，双击里面的东西直接用系统默认程序打开，拖出去就还原到目标位置。关掉控制中心它们照样在，托盘图标里随时能退。

---

## 设计决定（为什么这么做）

这些是开发前逐条确认过的边界，写在这里免得日后自己忘了当初为什么这么定。

| 决定 | 选择 | 理由 |
|---|---|---|
| 收纳机制 | 真移动文件 | 假隐藏会让文件在资源管理器里也「失踪」，用户会以为丢了 |
| 盒子粒度 | 多个具名盒，手工建 | 单一盒子很快变成另一个乱桌面；自动分流规则误判反而添乱 |
| 存储位置 | `%USERPROFILE%\DeskTidy\` | 放桌面上的话，整洁效果打对折 |
| 扫描源 | 用户桌面 + 公共桌面 | 公共桌面图标视觉上也是桌面的一部分，只收一半等于没收干净 |
| 重名冲突 | 自动加序号，绝不覆盖 | `报告.docx` → `报告 (2).docx`；弹窗会打断批量操作的流畅感 |
| 批量失败 | 继续处理，最后报告失败清单 | 回滚要再移动一次、还可能再失败，得不偿失 |
| 撤销粒度 | 只保留「上一次」整批 | 完整历史属于过度设计 |
| 图标位置 | **不记录** | 读 Shell `IFolderView` 内存映射是另一套高成本技术，不在本工具范围 |
| 配置持久化 | 盒子靠扫描重建，只有状态进 QSettings | 文件系统即真相，避免两份数据打架 |
| 常驻 | **常驻**，但不做开机自启 | 浮窗要一直在桌面上；关主窗口只隐藏，托盘退出才真退出 |
| 浮窗双击 | 打开（主窗口仍是还原） | 浮窗是「使用」界面，主窗口是「管理」界面，两种直觉各自成立 |
| 浮窗拖出 | 拖到哪就移动到哪 | 见下方「拖出还原」一节——这条是靠实测才敢做的 |

> 最后两条是后来加的。最初定的是「不常驻、只手动打开」，加了浮窗之后那条被推翻了，
> 这里记下来免得日后困惑。

## 浮窗

一个盒子 = 桌面上一个小窗。它做的事：

| 操作 | 效果 |
|---|---|
| 拖标题栏 | 移动浮窗位置（位置会记住） |
| 双击标题栏 | 卷起成一条 / 展开 |
| 双击条目 | 用系统默认程序打开它 |
| 拖条目出去 | **移动到**目标位置（拖到桌面就回桌面，拖到别的文件夹就进那儿） |
| 拖文件进来 | 归入这个盒 |
| 「收纳桌面」 | 把桌面收进**这个浮窗代表的盒**（不是控制中心当前选中的盒） |
| 「撤销」 | 撤销上一次收纳，按钮上会点名是哪个盒的 |
| 右键 → 外观 | 改显示方式（列表/大中小图标）与透明度 |
| 右键 → 其他 | 总在最前开关、卷起、还原此条目、在控制中心中显示 |
| `✕` | 关掉这个浮窗（下次打开程序不会自动恢复） |

**浮窗不占任务栏、不进 Alt+Tab、默认置顶。** 看全屏视频被挡的话，右键关掉「总在最前」。

## 自定义浮窗外观

**每个收纳盒各自一套**，互不影响。两个入口都能改：

- **浮窗上右键 → 外观**（改完立即生效）
- **控制中心左栏右键 → 外观设置…**（带实时预览的完整对话框）

可调项：

| 项 | 取值 | 说明 |
|---|---|---|
| 显示方式 | 列表 / 小图标(16px) / 中图标(32px) / 大图标(64px) | 图标模式会自动把窗口调大到够用 |
| 透明度 | 20% – 100% | 下限卡在 20%，**不会让你把浮窗调到看不见** |

**几个设计取舍**：

- **切到大图标会自动变大，但切回小图标不会自动缩小。**
  因为窗口尺寸可能是你自己特意拉大的，程序自动改掉会很烦。
  代价是切回小图标后右边可能留白，你自己拉一下就好。
- **透明度下限是 20% 而不是 0。** 0% 会让浮窗彻底看不见，而你没有入口把它调回来 ——
  那是不可恢复的故障，所以干脆不给这个选项。
- **外观存在配置文件里，不存进盒子目录。** 删掉某个盒时，它的外观配置也会一并清掉，
  免得将来建同名盒"继承"上一个盒的长相。

## 删除收纳盒

左栏右键 → **删除收纳盒…**

这个操作**不会丢文件**，但也不是简单地删目录：

```
1. 盒内文件先还原回桌面（重名自动加序号，绝不覆盖）
2. 还原不回去的（跨磁盘分区、被占用等）连同盒目录一起丢进回收站
3. 关掉该盒的浮窗、清掉它的外观配置
```

**确认强度按盒子是否为空区分**：

- **空盒**：普通确认框（它不移动任何文件，只是把一个空目录丢进回收站）
- **非空盒**：要求你**手动输入盒名**才放行

非空盒要输名字不是走形式 —— 它会移动真实文件，万一中途出问题，你看到的是"东西乱了"。
手输盒名强制你确认删对了盒子，防的是"删错盒"这个最贵的错误。

**为什么失败会中止而不是继续**：如果连盒目录都丢不进回收站（被占用、或磁盘不支持回收站），
流程会**整体失败并报错**，不会关浮窗也不会刷列表。因为盒目录还在磁盘上，
下次扫描还会出现 —— 此时若界面显示"已删除"，下次打开它又回来了，状态分裂比直接报错难查得多。

**删除不进撤销栈**：文件已经回桌面了，效果上等价于一次完整还原，再叠一层撤销语义
会让"撤销"到底撤销什么变得含糊。

## 拖出还原：一个必须实测才知道能不能做的功能

「把条目拖出去就该移动到那儿」听起来理所当然，但 Windows 默认不是这样。

**两轮实测的结论：**

1. **默认行为是复制。** 直接拖出去，目标处出现副本，源文件仍在盒里。
   `QDrag::exec()` 返回 `CopyAction`。做不到「拖到哪就还原到哪」。
2. **注入 `Preferred Drop Effect = MOVE` 后是移动。** 源文件消失、文件确实落在目标文件夹，
   返回 `MoveAction`。方案有效，实现见 `ui/preferreddropeffect.h`。

**但有一个必须遵守的硬约束**：方案成立的前提是**由资源管理器完成实际移动**，
我们只是告诉它「这是移动操作」。所以——

> 若用户把文件拖到**不接受文件拖放**的地方（某些程序、浏览器空白区），
> 对方不会执行移动，而我们的标记又让系统以为「会有人处理」。
> **实测中出现过文件既不在源、也不在目标、也不在回收站的情况。**

因此代码里有一道兜底（`ui/itemlistwidget.cpp` 的 `startDrag`）：
`exec()` 返回后**检查源文件是否仍存在**，而不是相信返回值。

- 源文件没了 → 资源管理器成功移走，静默刷新
- 源文件还在 → 对方没接手，**明确提示用户「文件仍在收纳盒中」**

这道兜底是防「文件凭空消失」的最后一道闸，不能删。

## 目录结构

```
DeskTidy/
├── DeskTidy.pro          Qt Creator 用（qmake）
├── CMakeLists.txt        Ninja / 命令行用（与 .pro 等价，改源文件清单需同步两处）
├── build.bat             一键构建脚本
├── verify.bat            一键验收（构建 + 全部测试）
├── main.cpp              装配：AppService -> FloatingBoxManager -> MainWindow -> TrayIcon
├── core/                 与界面无关的逻辑层
│   ├── coretypes.h       共享数据契约（唯一权威，其他模块不得重造）
│   ├── corenames.h/cpp   路径与命名纯函数（无 IO，便于单测）
│   ├── settings.h/cpp    QSettings 封装（排除项、浮窗状态）
│   ├── deskscanner.h/cpp 扫描两个桌面目录并过滤
│   ├── boxmanager.h/cpp  收纳盒的增删查（增=建目录，删=不做）
│   ├── collector.h/cpp   唯一执行真实文件移动的地方
│   ├── opener.h/cpp      用系统默认关联打开文件（只读，不动文件）
│   ├── undostack.h/cpp   只保留上一次收纳批次，供撤销
│   └── appservice.h/cpp  应用级状态中枢，core 层唯一带信号的类
├── ui/                   界面层
│   ├── mainwindow.h/cpp          控制中心：左右分栏 + 顶部按钮
│   ├── boxlistwidget.h/cpp       左栏：收纳盒列表
│   ├── itemlistwidget.h/cpp      条目列表（主窗口与浮窗共用，行为靠 Options 选择）
│   ├── previewdialog.h/cpp       收纳前预览确认
│   ├── floatingboxwidget.h/cpp   桌面浮窗本体
│   ├── floatingboxmanager.h/cpp  浮窗生命周期管理
│   ├── preferreddropeffect.h/cpp 让拖出变成「移动」的 Windows 转接器
│   └── trayicon.h/cpp            托盘图标与菜单
├── tests/                单元测试
│   ├── tst_corelogic.cpp         CoreNames 纯函数
│   ├── tst_appservice.cpp        MoveSummary 统计 + Settings 浮窗配置
│   └── tst_floatinglogic.cpp     浮窗相关逻辑
├── tools/                验收与实验探针（非产品代码）
│   ├── e2e_probe.cpp     端到端真实验证（收纳/重名避让/撤销）
│   ├── e2e_floating.cpp  浮窗信号链路验证
│   ├── drag_probe.cpp    拖放实验第一轮：测 Windows 默认行为
│   └── drag_probe2.cpp   拖放实验第二轮：验证「移动语义」注入方案
└── docs/                 设计文档
    └── DESIGN_FLOATING_BOXES.md  浮窗方案（含实测结论与未决风险）
```

分层原则：`ui/` 只调用 `core/`，`core/` 不认识 `ui/`。全部文件移动只能经由 `collector`。

## 配置文件

```
%LOCALAPPDATA%\DeskTidy\DeskTidy\DeskTidy.ini
```

> ⚠️ 是 **Local** 不是 Roaming。虽然 Qt 的常量名叫 `AppConfigLocation`，
> 但 Qt6 在 Windows 上把它映射到本地配置目录。

里面只存**状态**（排除项、哪些盒开了浮窗、各浮窗的位置与卷起状态），
**不存盒名清单**——盒子是磁盘上的真实目录，文件系统即真相。
删掉这个文件就等于重置所有设置，不会丢任何文件。

## 构建

本机环境（已实测）：

| 组件 | 路径 |
|---|---|
| Qt | `C:\Qt\6.11.1\mingw_64` |
| 编译器 | `C:\Qt\Tools\mingw1310_64\bin` |
| Ninja | `C:\Qt\Tools\Ninja` |

命令行构建：

```bat
build.bat
```

完整验收（构建 + 单测 + 端到端 + 浮窗链路）：

```bat
verify.bat
```

或 Qt Creator 直接打开 `DeskTidy.pro`。

## 使用

1. 打开 DeskTidy。
2. 左栏点「新建收纳盒」，起个名字（如「临时」「工作」）。
3. 选中盒子，点顶部「收纳桌面」，在预览对话框里确认要收哪些。
4. 桌面干净了。
5. 想让它常驻桌面：**右键左栏的盒子 → 「在桌面显示浮窗」**。
6. 要拿回来：在列表里双击某条，或点「撤销上次收纳」整批还原。

**退出程序**：关掉主窗口只是隐藏（浮窗和后台都在）。真正退出要从**托盘图标右键 → 退出**。

也可以直接把桌面上的文件拖进窗口，归入当前选中的盒子。

## 已知限制

- **不记录图标在桌面上的原始坐标**。还原后文件落在桌面的自动排列位置，
  不会回到它原来待的那个点。要做得读 Shell `IFolderView` 的内存映射，是另一套技术。
- **公共桌面来源的文件，单条还原时会落到用户桌面**。因为「这个文件当初来自哪个桌面」
  只存在于收纳那一刻的内存里，没有持久化。文件不会丢、不会改名，只是位置在用户桌面。
  整批撤销走撤销栈，`origin` 保留，不受影响。
- **不做开机自启**（需求明确没要）。
- **浮窗是直角，没有圆角半透明**。圆角要配 `Qt::WA_TranslucentBackground`，
  在 Windows 上牵涉无边框窗口的重绘时序，观感加分稳定性减分，留作后续打磨。
- **盒目录被程序外删除时浮窗会自动关闭**，但不会弹提示——下次打开控制中心即可看到它没了。
